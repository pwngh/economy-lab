The ledger is the product. One sibling package,
[@pwngh/economy-edge](https://github.com/pwngh/economy-edge), composes around it at runtime as
the front door to a real payout rail. [@pwngh/taskq](https://github.com/pwngh/taskq) is an
optional backend for the relay. Each enters through one seam, and each seam carries a guarantee.
Two more pieces read like packages and are not: the money arithmetic and the supervisor both
ship inside the lab.

## @pwngh/taskq — the optional relay backend

Committed postings emit events through [the outbox](/economy/ports/messaging/), and the relay
delivers them at least once. @pwngh/taskq turns those deliveries into durable work. The bridge's
dispatcher enqueues every event as a task, keyed by the event id:

```ts
// economy/lib/taskq-host.ts — the bridge's Dispatcher
const worker = taskq.startWorker(db, { queues });
const dispatcher: Dispatcher = async (event) => {
  await taskq.enqueue(
    db,
    'economy.events',
    {
      id: event.id,
      type: event.type,
      version: event.version,
      occurredAt: event.occurredAt,
      subject: event.subject,
      data: event.data,
      audience: event.audience,
    },
    { key: event.id },
  );
  worker.poke();
};
```

The `key` makes the enqueue idempotent: the relay's at-least-once delivery collapses to exactly
one pending task per event. Consumers inherit @pwngh/taskq's retries instead of writing their own.
The bridge is opt-in, through either of two names. `TASKQ=1` puts the task table in the ledger's own
database, which is what lets an enqueue share the ledger's transaction; a memory ledger has nothing
to live beside, so `TASKQ=1` without a `postgres://` or `mysql://` `DATABASE_URL` throws at startup
rather than delivering nothing. `TASKQ_DATABASE_URL` is the split-deployment override: it opts in on
its own and its scheme picks the engine, so a task table can sit on a different database from the
ledger. Either way `@pwngh/taskq` is an optional peer dependency and must be installed. The core
never sees it.

## @pwngh/economy-edge — the runtime sibling

Every payout rail satisfies the same [`Processor` port](/economy/ports/processor/). The edge
package owns one real rail's dialect — Tilia — and the host swaps it in at composition time:

```ts
// economy/lib/host.ts — read once at module load, before createApp opens the ports
const edge = await maybeEdgeTilia(env, logger);
if (edge !== undefined) {
  ports.processor = edge.processor;
}
```

The bridge is off unless `TILIA_CLIENT_ID` is set, and the package is an optional peer dependency.
Without it installed, the lab composes exactly as before. When it is on, four things change. The
shimmed processor replaces the env-selected one. The edge's hosted-KYC directory feeds the
[`PAYEE_UNVERIFIED` gate](/economy/reference/operations/request-payout/). The edge's wallet
balance feeds the float-coverage sweep. `POST /webhooks/tilia` routes the rail's callbacks into
the inbox. [The processor page](/economy/ports/processor/) owns how the shim maps the rail onto
the port.

## Not a package: the money arithmetic

The lab's money is its own source, in two files. `src/money-arithmetic.ts` is bigint minor-unit
arithmetic with its 171 conformance vectors embedded, and `src/money-sql.ts` carries the same
semantics as installable SQL routines. Both import nothing, which is how the ledger's arithmetic
adds no runtime dependency.

A database is never trusted to agree — only proven. Fifty-seven of the vectors, the division,
multiply-divide and basis-point families, run against the live engine at every boot, beside the
schema check:

```ts
// packages/postgres/src/postgres.ts — inside postgresStore's boot, beside assertSchemaCurrent
await installPostgres(runner);
assertMoneyConformant(await provePostgres(runner, moneyVectors), 'Postgres');
```

If the database computes even one vector differently — a rounding mode, a split remainder — boot
fails before any posting trusts it. The MySQL twin runs the same pair in `packages/mysql`.
`test/money-arithmetic.test.ts` runs all 171 against TypeScript, and
`test/conformance/money-db.test.ts` proves both engines against them in continuous integration.

## Not a package: the supervisor

The supervisor ships built in at the
`@pwngh/economy-lab/supervisor` entry point, composed host-side behind `SUPERVISOR=1`. The core never
imports it — leaving it out of the composition is the off switch.
[The supervisor](/economy/ops/the-supervisor/) owns it.
