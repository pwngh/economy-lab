The supervisor is an in-process library at the `@pwngh/economy-lab/supervisor` entry point. It lives
in the tree at `src/supervisor`, but the dependency runs one way. The core never imports the
supervisor, and an eslint boundary enforces that direction. The supervisor observes only
through the `meter` and `logger` ports the composition already carries. It acts only through
levers the host hands it. Leaving it out of the composition is the off switch. The lab cannot
tell whether it is being observed.

## Signal capture

`createSupervisorRuntime` wraps the host's meter and logger. It forwards every call unchanged and
copies each into a bounded in-memory ring (default 10,000 signals). Detectors read the buffer
through `SignalFeed.since(t)`. Log entries are buffered as name and level only. Field
payloads never outlive the host's own log pipeline.

The [worker](/economy/reference/background-worker/)'s lifecycle sweeps feed the same capture:
the accrual drain's backlog and oldest-row age, the orphan sweep's open-session gauge, the
re-proof's watermark age, and the archive and retention sweeps' move and delete counts. A
wedged drain or a stalled re-proof pass is therefore visible in the ring the same way a
payout backlog is.

```ts
import { openPorts } from '@pwngh/economy-lab';
import { createSupervisorRuntime } from '@pwngh/economy-lab/supervisor';

const runtime = createSupervisorRuntime({ meter, logger, clock });
const ports = await openPorts(env, {
  meter: runtime.meter,
  logger: runtime.logger,
});
```

## The signatures

Detection is a fixed set of plain threshold rules — no models, no inference. There are twelve
signatures and, in practice, three autonomy tiers: report, escalate, or act. The runbooks
number the tiers. Tier 1 remediates automatically. Tier 3 never changes state on its own. It
reports, and it escalates when money is at risk. Every signature links its
[runbook](/economy/ops/runbooks/).

| Signature | Response |
| --- | --- |
| [stuck-saga](/economy/ops/runbooks/stuck-saga/) | Act: one guarded worker sweep, verified by re-reading the saga. |
| [outbox-backlog](/economy/ops/runbooks/outbox-backlog/) | Act: a targeted relay re-drive, verified against the next backlog gauge. |
| [inbox-dead-letter](/economy/ops/runbooks/inbox-dead-letter/) | Act: revive the oldest dead rows; the normal drain re-applies them. |
| [integrity-mismatch](/economy/ops/runbooks/integrity-mismatch/) | Escalate and contain: prove once, pause the worker, never fix. |
| [engine-stall](/economy/ops/runbooks/engine-stall/), [treasury-breach](/economy/ops/runbooks/treasury-breach/), [signal-silence](/economy/ops/runbooks/signal-silence/), [retry-exhaustion](/economy/ops/runbooks/retry-exhaustion/) | Escalate with the evidence attached. |
| [deadlock-storm](/economy/ops/runbooks/deadlock-storm/), [velocity-anomaly](/economy/ops/runbooks/velocity-anomaly/), [webhook-replay-storm](/economy/ops/runbooks/webhook-replay-storm/), [checkpoint-seal-slow](/economy/ops/runbooks/checkpoint-seal-slow/) | Advise, once per window. |

## The guardrails

Every automatic action runs under the same mandatory pattern: `detected` → `decided` →
`acted` → `verified`, with `escalated` when automation gives up. The supervisor records each
phase in the [audit trail](/economy/ops/audit-trail/).

- **Cooldown** — `actionCooldownMs` sets the minimum gap between actions per subject. A
  repeat inside the gap audits as `suppressed`.
- **Attempt cap** — at `maxActionAttempts`, the action converts into a permanent escalation.
  Automation never touches that subject again.
- **Verification** — the supervisor checks every action by re-reading what it should have
  changed: the saga's state, the next backlog gauge, or the revived rows.
- **Containment** — an integrity episode latches a flag that refuses every lever until the
  supervisor restarts. The episode also pauses the worker's scheduled loop through
  `pauseWorker`. The supervisor never resumes a paused worker. A human does.

The supervisor's whole vocabulary is two moves. It calls a host lever (`runSweep`, a targeted
`runRelay`, `reviveInbox`, `pauseWorker`, a read-only `prove`), and it writes its own audit
record. It never writes ledger state and never mutates config. Detector state lives only in
memory and is lost on restart — deliberately, so a fresh process starts from observed
reality.

## Composing it

An app states `flags.supervisor` and `createApp` builds the supervisor next to the worker, wraps the
meter and logger in the signal buffer, and ticks it on `WORKER_INTERVAL_MS`. This repository's own
module compiles the `SUPERVISOR=1` environment name into that flag:

```ts
// the module seam, one line
export const flags = { supervisor: true };
```

The flag was `ops` through 0.7.0. A module that still states it is refused at boot with
`UNKNOWN_EXPORT` naming the new spelling, rather than composing without a supervisor.

Composing it by hand is the other way, and it is what a host does when it wants levers beyond the
sweep — a targeted `runRelay`, an inbox `reviveInbox`, a `pauseWorker` latch, or an audit sink of
its own:

```ts
const runtime = createSupervisorRuntime({ meter, logger, clock });
// compose the economy with runtime.meter and runtime.logger, then:
const supervisor = createSupervisor(
  {
    clock,
    signals: runtime.signals,
    sagas: ports.store.sagas,
    runSweep: (now) => worker.sweep({ now }),
    runRelay: (now) => worker.sweep({ now, only: ['relay'] }),
    reviveInbox: (n) => ports.store.inbox.reviveDead(n),
    pauseWorker: () => worker.pause(),
    audit: jsonlAuditSink((line) => process.stdout.write(`${line}\n`)),
  },
  intervalScheduler(),
);
```

Three demos wire the whole loop against a real in-memory economy: `make demo-ops` (the
stuck-saga closed loop), `make demo-ops-integrity` (tamper, prove, escalate, pause), and
`make demo-ops-deadlock` (a retry-pressure storm against a live SQL engine). The full export
surface is on the [generated reference](/api/modules/supervisor.html).
