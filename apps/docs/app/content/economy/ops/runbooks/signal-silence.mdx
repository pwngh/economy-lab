This is a [Tier 3](/economy/ops/the-supervisor/) signature, report-only. A signal the host declared as periodic has gone
quiet. The process that should emit it is down, paused, or wedged. Nothing downstream will say
so on its own.

## Symptoms

None, by definition — the missing beat is the whole symptom.

## Detection

The detector checks each declared watchdog (`watchdogs: [{ signal, everyMs }]` in
`SupervisorConfig` — e.g. `worker.sweep` on the sweep interval). A finding fires when no
matching signal arrives for more than twice `everyMs`. The clock runs from the later of the
last beat and when watching began, so the detector also catches a worker that never started.

## Automatic response

The supervisor emits `detected` + `escalated` once per silence episode, per watchdog. The
episode resets when the beat returns, so a flapping process escalates each time it dies.

## Manual steps

1. Start with the worker process — it is the usual cause of `worker.sweep` silence. Check the
   deployment is running, and reproduce locally with `make worker`.
2. Before restarting anything, rule out an intentional pause — a paused worker is also silent.
   Check whether an [integrity-mismatch](/economy/ops/runbooks/integrity-mismatch/)
   containment paused it on purpose (`worker.sweepsPaused`).
3. If the process is up but still emitting nothing, treat it as wedged: capture a thread dump,
   restart it, and check [engine-stall](/economy/ops/runbooks/engine-stall/) — a hung pool
   acquire inside a sweep looks exactly like this silence from the outside.

## Escalation

A silent worker means payouts, subscriptions, relays, and checkpoint audits have all stopped.
Treat recovery as urgent. Escalate to whoever owns the deployment if a restart does not bring
the beat back.
