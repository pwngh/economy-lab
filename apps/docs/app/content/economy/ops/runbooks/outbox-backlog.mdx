This is a [Tier 1](/economy/ops/the-supervisor/) signature with an automatic re-drive. Pending outbox events are aging past
threshold. The relay is down, its dispatcher is failing, or the events are poisoned.

## Symptoms

Downstream consumers stop receiving events while money keeps moving. `worker.relay.backlog`
(depth) and `worker.relay.backlog_age_ms` (oldest pending age) grow run over run.

## Detection

The relay sweep observes `OutboxStore.stats()` at the start of every run and emits the gauge
pair. The detector reads the newest `worker.relay.backlog_age_ms` sample. A sample at or past
`outboxBacklogAgeMs` (default 5m) is a finding. The store computes the age on its own clock —
app/database skew cannot fake it.

## Automatic response

The supervisor runs `detected` → `decided` → the `runRelay` lever. That lever is a targeted
`worker.sweep({ only: ['relay'] })`. It runs the relay job and nothing else (no checkpoint
sealed, no payouts advanced). It falls back to the full `runSweep` when the host wired no
relay lever. Verification spans ticks. The re-drive's own gauge still shows the pre-action
backlog, so the pass reads the first sample newer than the action and emits `verified` as
`drained` or `unchanged`. The standard guardrails apply: cooldown, attempt cap into permanent
escalation, containment suppression.

## Manual steps

1. If `verified` reported `drained`, the re-drive already cleared the backlog. The queue is
   healthy; move on to finding why the scheduled relay was not running on its own (see
   [signal-silence](/economy/ops/runbooks/signal-silence/)).
2. If `verified` reported `unchanged`, the re-drive ran but the backlog did not move — the
   dispatcher itself is failing. Read the `worker.relay.failed` / `worker.relay.dead_lettered`
   logs for the failure codes, and check the transport (SQS queue, HTTP bus, taskq bridge)
   directly.
3. List any poisoned rows that have hit the attempt cap and dead-lettered — they carry
   `status = 'dead'` with a reason recorded, parked so they cannot block the queue behind them:
   `select id, attempts, dead_letter_reason from outbox where status = 'dead';`
   A reason of `WORKER.ATTEMPTS_ABANDONED` names a different fault from the rest: no delivery ever
   came back to report one. The event took the relay process down every time — a hang, a crash, an
   out-of-memory kill — so the owner to page is the worker's, not the transport's.
4. Re-drive the relay by hand whenever you need to — run
   `worker.sweep({ only: ['relay'], dispatcher })` from any host shell. This is always safe to
   repeat: delivery is at-least-once and consumers dedupe by event id, so a duplicate re-drive
   cannot double-deliver.

## Escalation

The attempt cap escalates on its own with the advisory attached. From there the question
belongs to the transport's owner. The events are durable and waiting. Nothing is lost, only
late.
