Every pass the supervisor runs emits `AuditRecord`s to a sink the host injects. Each record
carries `at`, `signature`, `tier`, `phase` (`detected`, `decided`, `acted`, `verified`,
`escalated`), `subject`, and `detail`. The sink is the only place the trail persists: detector
state stays in memory, which makes the audit trail the one durable account of what the
supervisor saw and did.

## The plain sink

`jsonlAuditSink` writes one JSON line per record. Bigint money fields, such as a prove
report's drift amounts or a saga's reserve, encode as `{"$bigint":"..."}`. That is the
operation-journal convention, and it lets every line parse with plain `JSON.parse`.

## The chained sink

A plain trail is only testimony — anyone who can edit the file can rewrite it.
`hashChainedAuditSink` turns it into evidence by applying the ledger chain's fixed-preimage
discipline to the trail itself. Each line carries
`prev` and `hash`. `prev` is the prior line's hash, and the first line carries the all-zero
genesis. `hash` is computed over the line's own bytes. Editing a record, rewriting a `prev`,
dropping a line, or reordering breaks the chain at exactly that line.

```ts
const sink = hashChainedAuditSink(
  (line) => appendFileSync(segment, `${line}\n`, { flag: 'a' }),
  systemDigest(),
);
// ... records flow during the process's life ...
await sink.flush(); // the digest is async; flush before exit
```

`verifyAuditChain` re-derives a trail and reports in the prover's shape. The report states
whether the trail is intact, the first break with its line number and reason (`malformed`,
`broken-link`, or `tampered-hash`), and the count of lines verified.
`make audit-verify FILE=<segment>.jsonl` wraps it and exits nonzero on a break.

## Shipping to write-once storage

A chain proves tampering happened. Write-once storage keeps the honest copy. The worked
example in `scripts/audit-worm.ts` appends through the chained sink to a segment file opened
`O_APPEND`. It seals the segment by renaming it `*.sealed.jsonl`. The host ships the sealed
segment, for example to an object-lock bucket or a retention-locked store. The last line's
`hash` is the segment's fingerprint. Record the fingerprint off-host. The shipped copy, the
local copy, and the fingerprint must then all agree. The observer must be as tamper-evident
as the observed.
