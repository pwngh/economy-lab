The library ships a curated, faceted [`exports`](https://nodejs.org/api/packages.html#exports) map. The main package carries the day-to-day surface. Each subpath is a focused entry point. Install the package, then import from whichever path you need.

```bash
npm install @pwngh/economy-lab
```

```ts
import { createEconomy, topUp, toAmount } from '@pwngh/economy-lab';
import type { Store } from '@pwngh/economy-lab/ports';
```

| [`@pwngh/economy-lab/ports`](/api/modules/ports.html)                 | The port interfaces you implement to plug in your own infrastructure.                |
| [`@pwngh/economy-lab/adapters`](/api/modules/adapters.html)           | The bundled in-memory and HTTP adapters, plus the runtime services.                  |

| [`@pwngh/economy-lab/server`](/api/modules/server.html)               | The full HTTP surface: the server internals and the webhook intake.                  |
| [`@pwngh/economy-lab/netting`](/api/modules/netting.html)             | The in-instance netting session.                                                     |

## How the surface is split

The main package also re-exports the principal **ports** types. Everything else lives only on its subpath. The **driver-carrying** entry points load a database driver, so import each one only where its driver is installed. The engines carry `pg`, `mysql2`, and `mariadb`. The Redis and SQS adapters instead adapt an already-connected client you pass in, so they load with nothing installed.

The MariaDB entry point is an opt-in behind the same `MysqlPool` seam the MySQL store rides. The store, the schema, and the SQL stay the same. Only the wire protocol changes. See [the storage port](/economy/ports/storage/).

The main entry re-exports the **worker** and **server** constructors and their types. Their subpaths add the internals: the sweep names and batch shapes, the wire codec, and the webhook intake.

The **supervisor** is an in-process library that the core never imports. To switch it off, leave it out of the composition. It observes only through the `meter` and `logger` ports. It remediates only through host-provided levers, and mandatory guardrails bound every remediation. [Ops & runbooks](/economy/ops/) owns the operational story.

**store-kit** is what a conforming implementation computes with: the same chain hashes, balance deltas, orderings, and wire encodings the built-in engines compute. The suites that test an implementation against that contract live in their own package, `@pwngh/economy-conformance`, reached through `economy/conformance`.
