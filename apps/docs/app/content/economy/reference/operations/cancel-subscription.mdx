<ApiLink to="variables/economy-lab.cancelSubscription" /> marks an active [`Subscription`](/economy/concepts/subscriptions/) `CANCELED`,
so the [background worker's](/economy/reference/background-worker/) renewal sweep stops billing
it. It moves no money.

You submit it with the subscription id alone:

<CallTabs name="cancel-subscription" http={cancelSubscriptionHttp}>

```ts
const outcome = await economy.submit(
  cancelSubscription({
    idempotencyKey: 'cancel_sub_abc',
    actor: userActor('usr_a'),
    subscriptionId: 'sub_abc',
  }),
);
// → { status: "committed", transaction: { id: "txn_…", … } }
```

</CallTabs>

Canceling forfeits the rest of the period already paid for. There is no refund, so
there is nothing to post to the ledger.

Declines are returned data. Narrow on `detail.reason`:

```ts
if (outcome.status === 'rejected') {
  if (outcome.detail.reason === 'UNKNOWN_SUBSCRIPTION') {
    const { subscriptionId } = outcome.detail; // no active record matched the id
  }
  if (outcome.detail.reason === 'ECONOMY_PAUSED') {
    const resumesAt = outcome.detail.resumesAt; // when the maintenance window ends, or null
  }
}
```

## Parameters

The payload fields, beyond the `kind` tag, are:

| Field            | Type                                                       | Default    | Description                                                                                                                             |
| ---------------- | ---------------------------------------------------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `idempotencyKey` | `string`                                                   | (required) | Dedupes retries under the same key. See [idempotency](/economy/concepts/idempotency/).                                 |
| `actor`          | [`Principal`](/economy/concepts/actors-and-authorization/) | (required) | Who is asking. A `user` actor may cancel only their own subscription; a `system` or `operator` actor may cancel anyone's.                |
| `subscriptionId` | `string`                                                   | (required) | The subscription to cancel. Non-blank.                                                                                                   |

## Returns

`cancelSubscription` resolves to an [`Outcome`](/economy/reference/outcomes-and-reason-codes/).

- `committed`: the subscription is `CANCELED`. The placeholder
  [`Transaction`](/economy/concepts/accounts-and-double-entry/) carries empty legs. No money moves.
- `duplicate`: a repeat of the same `idempotencyKey`.
- `rejected`: the subscription is missing or already `CANCELED`, with
  `UNKNOWN_SUBSCRIPTION`. See [Reason codes](#reason-codes).

## Postings

None. A cancel is a status change only, so the placeholder transaction posts no
[double-entry](/economy/concepts/accounts-and-double-entry/) legs and advances no
account's hash chain.

## Authorization

A [`user`](/economy/concepts/actors-and-authorization/) actor may cancel only their own
subscription. The handler loads the record and compares its owner to the actor's `userId`.
A mismatch throws `AUTH.UNAUTHORIZED`.

A `system` or `operator` actor may cancel anyone's subscription. `cancelSubscription` is
not a privileged-only operation.

<Callout type="note">
  The central [authorization](/economy/concepts/actors-and-authorization/) check
  can't enforce ownership here. A cancel debits no user account, so the
  ownership rule has nothing to inspect. The handler checks ownership itself,
  against the loaded subscription.
</Callout>

## Reason codes

`cancelSubscription` returns these [reason codes](/economy/reference/outcomes-and-reason-codes/)
as a `rejected` outcome:

| Code                   | When                                                                                          |
| ---------------------- | --------------------------------------------------------------------------------------------- |
| `UNKNOWN_SUBSCRIPTION` | No subscription matches the id, or it is already `CANCELED`.                                  |
| `ECONOMY_PAUSED`       | A maintenance window is in effect and the actor is a `user`. The decline carries `resumesAt`. |

A malformed request throws instead:

| Code                | When                                                                                             |
| ------------------- | ------------------------------------------------------------------------------------------------ |
| `OP.MALFORMED`      | A blank or whitespace-only `subscriptionId`. Malformed client input, caught before the store is touched. |
| `AUTH.UNAUTHORIZED` | A `user` actor cancels a subscription they do not own.                                            |

## Preconditions and invariants

The handler confirms the subscription exists and is cancelable before it runs the ownership
check. So a probe with a missing or already-canceled id returns the same `UNKNOWN_SUBSCRIPTION`
answer regardless of caller. The answer never reveals whether the id exists.

Canceling is final for that record. A `CANCELED` subscription stays canceled. A second
cancel of the same id returns `UNKNOWN_SUBSCRIPTION` rather than committing again. To bill the
same SKU and seller again, the user runs [`subscribe`](/economy/reference/operations/subscribe/)
to open a fresh subscription.

<Callout type="warning">
  Cancel takes effect immediately and forfeits the rest of the paid period.
  There is no proration and no refund.
</Callout>
